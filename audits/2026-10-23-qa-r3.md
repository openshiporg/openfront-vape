## Major

### QA-037: A successful save in the Classify sheet crashes the product page to "Something went wrong"
- **Area:** dashboard (main merchant workflow)
- **URL:** `/dashboard/platform/products/cmvlcvaf30001pr0x0fb60auf`, then Compliance, then **Classify** or **Edit**
- **Steps:** Fill in a valid draft classification (or edit the existing QA draft) and click Create/Save classification.
- **Expected:** The toast "Classification saved", the sheet stays open with the Authorizations section, and the Compliance row updates.
- **Actual:** The whole page is replaced by the dashboard error boundary ("Something went wrong. An unexpected error occurred in the dashboard. Please try refreshing the page."). The console shows `Minified React error #441` (an error in the Server Components render) and "Dashboard operation failed (details redacted)." The data **is** saved: after a reload the row says "Classification draft", with specs "50 mg/ml · 2 ml · QA Tobacco R3". Reproduced twice, once on create and once on update. A save that fails validation does not crash: it shows the hook message inline. So a merchant sees a crash every time they get it right, and can't move on to the Authorizations section in the same visit.
- **Likely file:** `features/platform/products/actions/classify.ts:171` and `:194`. `revalidatePath('/dashboard/platform/products')` in the server action makes Next re-render the current product route's Server Components inside the action response, and that render throws. Check the `ProductItemPage` server screen for code that assumes a normal request (cookies or headers, `notFound`, redirect). Or drop the `revalidatePath` and rely on the client `loadCompliance()` refresh that `ClassifySheet` already calls through `onSaved`. `saveAuthorization` has the same call. Railway logs will hold the digest.

### QA-038: The Compliance Center's new "Add approval" sheet never loads ("Unable to load compliance records.")
- **Area:** dashboard
- **URL:** `/dashboard/platform/compliance`. Any "Add approval" button, in Blockers or in Providers.
- **Steps:** Click "Add approval" on "No registry provider approval" (or Payment).
- **Expected:** The provider-approval form, with the profile, provider, product types, jurisdictions, reference, evidence upload and dates.
- **Actual:** The sheet opens with the title "Registry provider approval" and only the text "Unable to load compliance records." Tried with two purposes and on two page loads, with the same result. The same four reads that `getApprovalOptions` makes (merchant profiles, payment providers, shipping providers, jurisdictions) all succeed when sent to `/api/graphql` with the same admin session. So the failure is in the server action itself, not in access. Five of the nine blockers send the merchant here, so none of them can be cleared from the Compliance Center now. The old fallback (the generic `/dashboard/provider-approvals/create`) is no longer linked from these rows, and it still masks errors (QA-026).
- **Likely file:** `features/platform/compliance-center/actions/approvals.ts:31-47`. The bare `catch { return null; }` hides the cause, so log `error.name` and the Keystone error code first. Compare with `getClassifyForm`, which uses the same `sessionContext()` and works. Also `features/platform/compliance-center/components/ProviderApprovalSheet.tsx:92-101`.

### QA-039: Sign-up rejects a short password with "The supplied details are invalid" and wipes the whole form
- **Area:** storefront
- **URL:** `/us/account`, then Create account
- **Steps:** Fill in every field with a 6-character password, tick 21+, and submit.
- **Expected:** "Password must be at least 10 characters" next to the password field (the User model requires 10+ and rejects common passwords). The other fields keep their values, and the field has `minLength={10}` and a hint, as the new reset form already does.
