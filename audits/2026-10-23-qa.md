## Blockers

### QA-001: Production CSS is the pre-redesign build, so every `vp-*` design token and component class is missing
- **Area:** storefront (every page)
- **URL:** https://openfront-vape-production.up.railway.app/us (all storefront routes)
- **Steps:** Load any storefront page. Fetch the served stylesheets (`/_next/static/chunks/3ecrytok-d9if.css`, `28c92q_qp7ss9.css`, `3d-1vk5hzu5rq.css`) and search them for `--color-vp-ink`, `.vp-pill`, `.vp-track`, `vape-sf` or `sf-background`.
- **Expected:** The CSS compiled from HEAD's `app/globals.css`: the `--color-vp-*` tokens (`#F1F2EF` ground, `#141816` ink and so on), the `.vape-sf` overrides and the `.vp-pill` / `.vp-track` / `.vp-band` components.
- **Actual:** None of them are in the served CSS. The served theme exactly matches the **old** `app/globals.css` from `41814c8`: `--color-background:#fff` (old `oklch(100% 0 0)`) and `--color-foreground:#030303` (old `oklch(9.65% 0 0)`). HEAD's version would compile to `var(--sf-background, …)`. The HTML *is* the new build (it has the `vape-sf` wrapper, Schibsted Grotesk and IBM Plex Mono, and the new markup). Only the Tailwind stylesheet is stale. As a result, `bg-vp-ink`, `bg-vp-well`, `text-vp-*` and `border-vp-line` all resolve to nothing. The page ground is white instead of mist, ink buttons are transparent, and segmented controls are bare text. QA-002 to QA-005 are all visible effects of this.
- **Likely cause and file:** `app/globals.css` is correct in HEAD. The problem is the build or deploy: most likely a stale Next/Turbopack CSS cache on Railway, or a build that ran against an older `globals.css`. Rebuild with a clean cache. Then check the deploy by grepping the served CSS for `--color-vp-ink` and `.vp-pill`. Also confirm that `next build` locally emits them.

### QA-002: The age gate's "Yes, I am 21+" button and the "21+ only" header strip are invisible
- **Area:** storefront (compliance-critical)
- **URL:** https://openfront-vape-production.up.railway.app/us (first visit, no `vp_age_21` cookie)
- **Steps:** Open the site in a fresh browser at 390px or desktop.
- **Expected:** An ink-filled "Yes, I am 21+" pill next to a grey "No" pill. A dark strip above the header reading "21+ ONLY · Adult signature may be required on delivery".
- **Actual:** The "Yes, I am 21+" button has a computed background of `rgba(0,0,0,0)` and white text on a white card. At 390px you only see it because of the autofocus ring. The "No" pill has no fill either. The header strip's text is `white/80` on a transparent background, so the age warning on every page can't be seen (computed colour `oklab(1 0 0 / 0.8)` on `rgba(0,0,0,0)`).
- **Likely file:** root cause is QA-001. The components are `features/storefront/modules/layout/components/age-gate/index.tsx` and `features/storefront/modules/layout/templates/nav/index.tsx:27-31`.

### QA-003: Primary buttons are white on white across the storefront (Sign in, Create account and every ink pill)
- **Area:** storefront
- **URL:** https://openfront-vape-production.up.railway.app/us/account (Sign in and Create account tabs)
- **Steps:** Go to Account. Look below the password field. Then switch to "Create account".
- **Expected:** A full-width ink "Sign in" or "Create account" button.
- **Actual:** There is empty space where the button should be. The button exists (it's 400×48), but its background resolves to transparent and its text is white. A customer can't see how to submit either form. Pressing Enter works: I created a customer account this way. The same `bg-vp-ink` / `primaryButtonClass` styling is used in about 28 storefront files, including the product page's add-to-bag (`modules/products/components/product-actions/index.tsx`, `mobile-actions.tsx`), the cart summary, checkout, addresses, invoicing and the empty-cart call to action. Expect all of them to be invisible too.
- **Likely file:** root cause is QA-001. The class is defined in `features/storefront/modules/account/components/account-ui/index.tsx` (`primaryButtonClass`).

### QA-006: Publishing a product fails with "Unable to complete the request" and never says why
- **Area:** dashboard (main merchant workflow)
- **URL:** https://openfront-vape-production.up.railway.app/dashboard/platform/products/cmvlcvaf30001pr0x0fb60auf
- **Steps:** Open "QA Test Pod R1" (Draft). Set Status to Published and click Save Changes.
- **Expected:** Either the product publishes, or an actionable error such as "Regulated product classification must be approved and current before publication" (the message `features/keystone/regulated/enforcement.ts` throws), with a pointer to where to fix it.
- **Actual:** A toast says "Failed to save changes". Its "Details" dialog only says "Error: Unable to complete the request. Please try again." The server action returned `{"errors":[{"message":"Unable to complete the request. Please try again."}]}`. The product stays Draft and the page keeps showing "Unsaved changes". A merchant has no way to learn that compliance evidence is missing. The same masking hits every validation error on every dashboard save.
- **Likely file:** `features/dashboard/lib/keystoneClient.ts:62-64` and `:135-137` replace every GraphQL error with `PUBLIC_REQUEST_ERROR`. `features/dashboard/lib/security.ts` already lists the safe `KS_VALIDATION_FAILURE` and `KS_ACCESS_DENIED` codes, but their messages are still thrown away. Pass through the validation and access-denied messages, which are safe and written for merchants. E-commerce has the same masking, but in Vape compliance rejections are the normal reason a save fails, so the impact is much higher here.
